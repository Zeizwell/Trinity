# ZX Trinity — концепт (актуально на 2026-10-17)

Звуковая карта для ZX Spectrum (ZX-BUS / NemoBus, ZX Evolution) на настоящих AY (TurboSound) — **три платформы в
одной, отсюда Trinity: Atari + Amiga + MSX**:
- **Atari** — таймерные эффекты поверх AY (SID, бузер, FM, свип), SNDH-плеер — RP-AY;
- **Amiga** — General Sound со звуком Paula и лучше (`doc/paula.md`), совместимость с GS / NeoGS — RP-GS;
- **MSX** — OPL4 (Moonsound) — RP-GS.
Подробности и история решений — `doc/zx-trinity.md`; протокол — `doc/ay-ports-map.md` п.5а; строка FX —
`FT2/doc/fx-row.md`; эффекты физически — `doc/bitphase-fx.md`.

## Состав карты

```
ZX-BUS (5 В) ──► CPLD: дешифрация портов, IORQGE, WAIT, уровни 5 / 3.3 В, стробы для RP
                   │
                   ├──► RP-AY (RP2350B) ──► 2 × YM2203 (SSG = AY + FM, панельки) ───────┐
                   │      тень регистров, ответ на чтение, таймерные эффекты              │  аналоговый
                   │                                                                      ├─ сумматор ─► линейный выход
                   └──► RP-GS (RP2350B + PSRAM 8 МБ) ──► I2S ──► PCM5102A ────────────────┘   (наушники — под вопросом)
                          движок GS, microSD
```

- **CPLD** (MAX3000A: EPM3064A / EPM3128A, ядро 3.3 В, входы терпят 5 В; или ATF1504AS) — всё быстрое и жёсткое:
  дешифрация портов, IORQGE, WAIT, готовые стробы каждой RP. Шина Спектрума не зависит от прошивок.
- **Запас на будущее** (пользователь, 2026-10-18): от CPLD к каждой RP — 4 линии кода устройства (1..15, 0 — нет):
  новые порты добавляются перепрошивкой CPLD, плата та же. Синтез «в цифре» (SAA1099, MIDI-синт и т.п.) — только
  на RP-GS (у неё ЦАП); RP-AY звучит только через AY.
- **Две RP, связаны:** UART (файлы с SD карты, команды, образ прошивки RP-AY) + RUN от RP-GS к RP-AY (RP-GS
  обновляет RP-AY с SD через её загрузчик; SWD у модулей не выведен). Модулями (без пайки QFN), прошивка файлом UF2 по USB. Без одной из RP линии молчат.
- **Без RP её часть молчит, шина цела** (решено 2026-10-19): обхода «CPLD пишет в AY» нет — чип связан только с
  RP-AY; без RP-GS порты GS не отвечают. Звук на Еве и так есть, прошивка RP чинится по USB.
- Работает на штатной Еве со штатной прошивкой TS-Config; свой форк TS-Config — только как ускорение.

## AY-часть: настоящие AY + таймерные эффекты

- **Чипы — 2 × YM2203** (решено 2026-10-18, раньше было «AY-3-8910, FM не ставим»): как в MultiSound / TurboSound FM.
  SSG-часть — AY (на ней эффекты), FM — живой; на каждый чип ЦАП YM3014B + ОУ + фильтр в сумматор. RP-AY пропускает
  все записи (протокол TS-FM: `#F8..#FF` в `#FFFD`), сама выдерживает паузы записи YM2203 и отдаёт busy — софту
  ждать не надо. Чипы у пользователя есть (с MultiSound).
- **RP-AY в разрыве шины AY:** ловит обращения к `#FFFD` / `#BFFD`, держит теневые регистры, на чтение отвечает
  сама, **в AY пишет только она** (с AY никто не читает — 5 В на RP не попадают).
- **Эффекты записью регистров AY** (как Bitphase), каждый на своём таймере:
  SID — громкость канала; Sync (бузер) — форма огибающей R13; FM — период тона; Env FM — период огибающей.
- Частота таймера — от периода тона канала, **всегда за тоном**; детюн в полутонах и сырой.
- PWM и свип — только при таблице из 2 шагов; скважность 16 ступеней 0..50 %; свип — 256 шагов фазы, форма —
  таблицей.
- Тон выключен + SID с таблицей из 16 уровней — **«Волна»** (форма волны таблицей, амижный чиптюн на AY).
- **Обмен — 2 номера регистра AY** (свободное от всех поле, мимо FM YM2203 и AYX-32):
  `#C0` — управление (ключ «TRIN» открывает, `0` закрывает, ресинхронизация, статус);
  `#C1` — поток пакетов `[код][данные]`: `ROW` (строка FX канала), `TABLE`, `RESET` (новая нота), `INFO`.
  Режим Тринити по умолчанию выключен. Запись — `OUT (C),A` с постоянным `BC`.
- **Плеер (FT2)** шлёт строку FX канала только при её смене; таблицы — при загрузке трека и при правке; карта
  крутит таймеры сама. Музыкальная логика (ноты, инструменты, команды паттерна) — в плеере, карта получает
  готовые параметры.

## GS-часть

- **Снаружи — GS и NeoGS (возможно со своими дополнениями), внутри — нативный движок, Z80 нет и не будет** (пользователь,
  2026-10-31). Команды ПЗУ: модули, сэмплы, эффекты в играх.
- Залитый в GS чужой код — **заплатки (HLE)**: узнаём по контрольной сумме, делаем то же нативно; неизвестный —
  «не поддерживается» + хэш в лог.
- Режимы звучания: Classic / Paula A500 / Paula A1200 / HiFi; без зеркальных частот (BLEP), без щелчков;
  8 каналов, 16 бит, PSRAM 8 МБ под сэмплы. SounDrive / Covox не делаем. Порядок: GS, потом OPL4, возможно XM и другие многоканальные форматы с ПК (пользователь, 2026-10-31).
- **NeoGS — по частям:** SD (ниже), больше памяти; MP3 — программно, позже; свой код под NeoGS — заплатками.
- **OPL4 (Moonsound) — тоже на RP-GS** (решено 2026-10-18): программная эмуляция YMF278B (ориентир — ymfm), ROM волн
  YRW801 (2 МБ) — файл пользователя (в публичной прошивке нет): прошивка один раз заливает его с SD во флеш RP-GS, дальше SD не нужна (пользователь, 2026-10-31), PSRAM — ROM + память сэмплов. Порты Moonsound (`#C4..#C7`,
  `#7E` / `#7F`) — в CPLD с первой ревизии, звук — прошивкой потом. Порты GS и OPL4 живут всегда, кто начал играть последним, выключает мешающего (`doc/zx-trinity.md` п.14д).
  Проверено (2026-10-18): MSX PicoVerse 2350 (github.com/cristianoag/msx-picoverse-public) играет OPL4 на RP2350 через
  ymfm как есть, 44.1 кГц, I2S-ЦАП, 2 МБ сэмплов в PSRAM; для тяжёлой полифонии — сборка на 22 кГц (значит, ymfm
  впритык). Цифр загрузки и частоты нет. Их код — CC BY-NC-SA (некоммерческий: не копируем), ymfm — BSD (берём).
- **Разделение RP:** RP-GS — GS + OPL4 (вся PSRAM — сэмплы и ROM волн); RP-AY — только AY: тень, эффекты, SNDH-плеер
  (`doc/trinity-sndh.md`; RAM Atari 2 МБ — PSRAM у RP-AY или урезанная во внутренней SRAM).

## SD-карта (microSD на RP-GS)

- Автообновление прошивок обеих RP с SD; страховка — USB BOOTSEL.
- **Совместимость с SD NeoGS** — заплаткой на известные драйверы (WC `SD_NGS`: заливают в GS ~1 КБ кода, дальше
  команды `#20` / `#10` / `#12` через `#BB` / `#B3`) — старые драйверы работают без изменений.
- Свой шлюз секторов — для FT2 (FAT32-драйвер берёт носитель таблицей порта) и форка WC.

## Звук

- Аналоговое сведение AY + GS, звёздная земля, аналог отдельно; цифра шины — подальше.
- Линейный выход. Усилитель на наушники, громкость — под вопросом. USB-крутилка — может быть, в следующей ревизии.

## Идея: SNDH-плеер в RP-AY (2026-10-18, не решено)

Музыка Atari ST (SNDH: код 68000 + YM + таймеры MFP) играется прямо в RP-AY: эмуляция 68000 и MFP, записи в YM -
в живой AY (SID, бузер, дижидрамы - кодом музыканта, мимо FX-регистров). Файл - с SD карты (через RP-GS по UART)
или с диска Евы (поток `#C1`, новый пакет «залить / играть / стоп»). Частота AY в этом режиме - 2 МГц (как у ST, если
такт AY даёт RP). STE-тунцы с DMA-звуком на AY не играют. Разбор плеера (AtariAudio, MIT) - `doc/trinity-sndh.md`.

## Не делаем

SAA1099, MIDI (в первой версии; потом — прошивкой через 4 линии кода), Wi-Fi, USB-клавиатура / мышь -> PS/2, «железная» Paula.

## Софт и эмуляция

- **FT2** — эффекты AY FX (редактор FX, плеер, пакеты), потом GS.
- **Unreal** (наша сборка) — устройство AY FX, переделать под новый протокол; **Xpeccy** — автор поддержит сам
  (документ для авторов эмуляторов — протокол + строка FX).

## Этапы

1. **Макет AY — сейчас:** RP2350B (Spotpear) в разрыве слота YM2203 на MultiSound (CPLD MultiSound уже делает
   дешифрацию — как будет на карте). Прошивка `D:\_Work\Speccy\Trinity\firmware\rp-ay`: шаг 0 собран; дальше —
   сквозная передача, тень, первый эффект, протокол.
2. Макет GS: RP2350B + PSRAM + PCM5102A — звук без шины, потом порты GS.
3. Схема карты (CPLD, две RP, 2 × YM2203 + 2 × YM3014B, аналог), плата, заказ.

## Принципы

Доступно всем (детали по ~1 $, пайка руками, двухслойная плата), всё открыто, AY живой, звуковой тракт — лучший
из карт, карта не зависит от своих прошивок Евы.
