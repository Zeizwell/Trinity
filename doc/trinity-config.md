# Trinity — конфиг решений

Пункт — ответ. Решили — правим здесь. Другие доки расходятся с этим файлом — верен этот файл.

## Состав
1. Чипы: 2 × YM2203 (SSG = AY, FM живой), панельки.
2. RP-AY: RP2350B, Spotpear RP2350B-MINI-A: флеш 16 МБ, PSRAM 8 МБ.
3. RP-GS: RP2350B + PSRAM 8 МБ, тот же модуль.
4. CPLD: EPM3128ATC100-10N.
5. ЦАП GS: PCM5102A (модуль GY-PCM5102), I2S 32 бита. Частота: все пресеты 48 кГц. Пересчёт «ROM GS» (только в Custom) - 37.5 кГц как GS (каждый отсчёт дважды, ЦАП на 75 кГц).
6. Выход: аналоговый сумматор AY + GS, линейный.

## Что где
7. AY-фичи: RP-AY.
8. GS-фичи: RP-GS.
9. Цифровой синтез: только RP-GS.
10. Чипами управляет: только RP-AY, у каждого чипа своя шина.

## Шина
11. Порты разбирает: CPLD.
12. CPLD -> RP-GS: код устройства, 6 бит.
13. CPLD -> RP-AY: код, 2 бита.
14. Новый порт: перепрошивка CPLD.
15. Выбор чипа TurboSound: RP-AY сама, после сброса `#FF`.

## RP-GS: устройства
16. Z80 внутри: нет, никогда.
17. Снаружи: GS и NeoGS, возможны свои дополнения.
18. Внутри: нативный движок.
19. Залитый чужой код: известный — заплатка, неизвестный — «не поддерживается» + хэш в лог.
20. Порядок работ (2026-11-10): GS, SD для Спектрума (п.42а), XM / S3M / IT (п.28), OPL4. Заплатки чужого кода (п.27а) - потом, кроме драйвера SD NeoGS.
21. SounDrive / Covox: нет.
22. Звук цели: аутентичная Paula и лучше.

## RP-GS: устройство прошивки
23. Слои: коре -> устройства -> движки.
24. Коре: шина, таблица устройств, PSRAM, SD, конфиг, API, микшер, I2S.
25. Устройство: протокол на портах. Файл + таблица + строка в списке.
26. Движки: каналы + Paula, MOD-плеер. MOD на 4 канала - как ProTracker по тикам (`gs_pt`), остальные MOD - pocketmod. OPL4 (ymfm): отдельный блок, с Paula не связан, живёт по своим законам.
27. GS и NeoGS: два устройства, один движок.
27а. Чужой код Z80, залитый в GS: ловим и пишем лог на SD карты (код, адрес, контрольная сумма, обмен с портами), потом реверс и заплатка на RP.
28. XM / S3M / IT: через команды GS - «загрузить модуль» принимает любой формат, карта узнаёт его по заголовку и играет своим плеером; старые плееры GS сами пускают только MOD, наши программы (плагин WC, плеер Trinity) шлют любой формат теми же командами. Подробный статус (ноты, каналы, сабсонги) - через API. Движок XM / IT / S3M / MOD - свой, на C; код PiCard Musica не берём. Эталон поведения - OpenMPT (им играют и пишут). Проверка на ПК: наш движок в пресете Clean против libopenmpt без интерполяции и без плавной громкости, на одной частоте. Сэмплы - 16 бит как есть.
28б. MIDI: через OPL4 (волны из ROM - набор GM), после OPL4 (пользователь, 2026-11-10).
29. Шина: прерывание, только быстро.
30. Ядро 1: звук.
31. Ядро 0: работа, служебное.

## Включение устройств
32. Профили: нет.
33. Перезапуск при смене: нет.
34. Порты GS и OPL4: живут всегда.
35. Звук считает: только то, что играет.
36. Запуск: «играть» GS, key-on OPL4. Опрос — не запуск.
37. Конфликт: кто начал последним, выключает мешающего.
38. Отключить устройство: настройка, маска портов в CPLD. По умолчанию всё включено.

## Прошивка и SD
39. Загружается: только прошивка, в ней всё.
40. Плагины с SD: нет.
41. Новые устройства и сервисы: при сборке.
42. Карта без SD: работает.
42а. SD для Спектрума: шлюз секторов в RP-GS, протокол GS-части драйвера SD NeoGS (`#20` init, `#10` читать, `#12` писать, сектора сырые по 512, FAT ведёт Спектрум; выход `#F3` / `#F4` - перезапуск GS). Вход: пакет `#D8` канала драйвера (SDK `Gsc_Sd_*`) или драйвер NeoGS, узнанный по отпечатку (WC `SD_NGS`). После выхода карта перемонтирует SD.
43. ROM волн OPL4: файл пользователя, не в публичной прошивке. Один раз с SD во флеш.
44. Прошивка RP: только из ОЗУ (`copy_to_ram`).
45. Прошивка CPLD: через RP-GS по JTAG, SVF.
60. PSRAM: без раздела, все 8 МБ у активного устройства. GS видит столько, сколько выставлено в программе-драйвере на Спектруме, по умолчанию 8 МБ.

## Настройки
45а. Каналы MOD: канон Амиги, L R R L, одна раскладка без перестановок.
46. Хранение: одна структура переменных, во флеше RP.
46а. Где менять: все настройки — в программе-драйвере на Спектруме.
46б. Нагрузка карты: видна в драйвере вживую, на играющей музыке: нагрузка сейчас, пик, опоздания, режим и частота. Пик и опоздания сбрасываются при смене настройки. Цифры - одна глобальная переменная в коре, общая для всех устройств: GS, XM, OPL4.
46в. Обновление прошивок (RP-GS, RP-AY, CPLD): файл на SD, при старте карта проверяет контрольную сумму и версию и шьёт сама. Драйвер показывает версии и результат, может запустить вручную.
46г. Канал драйвера: порты GS `#BB` / `#B3`, свободные команды за ключом `TRINITY`, новых портов нет. Если GS выключен маской (п.38), канал молчит: как включить обратно, не решено.
46д. Драйвер: только данные и настройки (протокол + SDK), без интерфейса. Интерфейс: отдельный слой, пишет кто угодно под свою конфигурацию.
47. DIP-переключатели настроек: нет.
48. Режимы звука - пресеты, список данными (сколько угодно): Clean, A500, A1200, HiFi, Custom. Clean - без всего: без интерполяции, эквалайзер и LED выкл; отдельного пресета GS нет. Пресет - запись: метод вывода, полосы эквалайзера, LED. На движок каналов (GS, XM), переключается на лету, OPL4 не касается. Часть пресетов вшита в прошивку (не правятся), остальные - пользователя (во флеше RP). По умолчанию: A1200.
48г. Эквалайзер: 10 полос (31 Гц .. 16 кГц, по октаве), -12..12 дБ, плюс предусилитель. Пресеты - положения полос: Плоский, A500 (RC 4.4 кГц со схемы), A1200 (плоский), HiFi (окраска); двинул полосу - Custom. Кривая видна в драйвере.
48в. Частота вывода: не настройка, следует за пересчётом (п.5). Остальные сочетания не запрещены, ручная правка — Custom.
48б. Clean - звук как есть, без обработки: ближайший отсчёт сэмпла на 48 кГц (без интерполяции и BLEP), все ступени выключены. Он же - режим сравнения с OpenMPT (п.28).
48а. LED Амиги: не полосы, а отдельный фильтр со схемы (3.1 кГц, 2-й порядок) и кнопка вкл / выкл, как на Амиге. Ручки НЧ / ВЧ: только в интерфейсе драйвера - двигают крайние полосы эквалайзера, своего фильтра нет.
