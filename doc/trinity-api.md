# API карты ZX Trinity — стандарт

Одно место для всех: прошивки RP, Unreal, SDK, FT2. Новая фича = новая строка в таблицах ниже, сам стандарт не
меняется. Почему так решили — `doc/zx-trinity.md` п.14а (состояния), 14в (сервисы), 14г (слоты / задания).
Статус строк: **есть** — работает (протокол v3, RP-AY v26, движок `engine/svc.c`, тест `engine/test`), **план** —
номер закреплён, кода нет.

## 1. Транспорт (RP-AY)

Регистры AY, которых нет у чипа, — через `#FFFD` (выбор) / `#BFFD` (данные), как обычный AY.
**Есть ли карта — один раз при старте, пакетом `INFO`** (ответ `"TRIN"` + версия); дальше `#C0` читается только как статус.

| Рег | Запись | Чтение | Статус |
|---|---|---|---|
| `#C0` | ключ `"TRIN"` (4 записи подряд) — открыть поток; `0` — закрыть; `#80` — метка «занята» (после служебного пакета, раздел 2); любая запись — начать разбор заново | **байт статуса** (раздел 3), в любой момент, без ключа | есть |
| `#C1` | поток пакетов (раздел 2) | ответ на последний пакет с ответом (ключ не нужен); ответа нет — тень | есть |
| `#C2..#CF` | запас | | |

Запись — `OUT (C),A` при постоянном `BC = #BFFD` (не `OTIR` / `INIR`: `B` — и счётчик, и адрес). Выбор TurboSound
(`#FF` / `#FE` в `#FFFD`) — как обычно, у каждого чипа свой поток. Сеанс: выбрать `#C0`, ключ -> выбрать `#C1` ->
пакеты подряд -> выбрать `#C0`, `0`. На чтение отвечает железо карты (`doc/zx-trinity.md` п.14е): ответ на регистр
считается при его выборе или записи — **перед чтением выбрать регистр** (SDK так и делает). Подробно про номера
регистров AY у других карт — `doc/ay-ports-map.md`.

## 2. Пакеты

Код `< #80` — **реалтайм** (плеер, каждый кадр): длина фиксирована, ответа нет. Код `≥ #80` — **служебные**:
`[код][длина 2 байта][данные]` (числа — младшим байтом вперёд), ответ — из `#C1`: `[длина 2 байта][данные]`.
Неизвестный реалтайм-код — карта пропускает байт; неизвестный служебный — ответ `FF`. Без ответа: `SLOT_WRITE`,
`SLOT_FREE`, `JOB_STOP`. Данные служебного пакета — до 517 байт.

**Служебный вызов (Z80):** ключ -> `#C1`: пакет -> выбрать `#C0`, `0`, `#80` (метка: с этого момента статус —
«занята», пока ответ не ляжет) -> выбор `#C0` и чтение статуса в цикле программы, пока бит 7 = 1 -> бит 6 = 1 — ответ
готов: выбрать `#C1`, прочитать длину и данные **целиком**. Следующий служебный пакет — только когда бит 7 = 0 (иначе
карта его пропустит). Между пакетом и чтением ответа — никаких других записей в `#C0` / `#C1` (плеер FX — придержать).
`INFO` — так же (ответ без длины: 5 байт).

| Код | Имя | Данные | Ответ | Статус |
|---|---|---|---|---|
| `1` | `ROW` | канал 0..2, строка FX 14 байт (`FT2/doc/fx-row.md`), форма, фаза, флаг свипа — всего 19 байт с кодом | — | есть |
| `2` | `TABLE` | номер таблицы, 16 значений | — | есть |
| `3` | `RESET` | маска каналов (новая нота) | — | есть |
| `4` | `INFO` | — | `"TRIN"`, версия протокола (сейчас 3) | есть |
| `#80` | `SLOT_NEW` | тип (4 знака), размер (4), флаги (бит 0 — постоянный) | номер слота / 0 — нет места (постоянные — пока 0) | есть |
| `#81` | `SLOT_WRITE` | слот, смещение (4), байты (до 512) | — | есть |
| `#82` | `SLOT_READ` | слот, смещение (4), сколько (2, до 512) | байты | есть |
| `#83` | `SLOT_INFO` | слот | тип, размер, флаги | есть |
| `#84` | `SLOT_FREE` | слот | — | есть |
| `#85` | `SLOT_LIST` | — | номера занятых слотов | есть |
| `#90` | `SVC_LIST` | — | число, по 26 байт: номер, версия, имя 16 знаков, тип входа (4), тип выхода (4) | есть |
| `#91` | `SVC_CALL` | сервис, команда, слот входа, слот выхода, параметры (до 8). Тот же сервис уже идёт — это команда ему (`PAUSE`, `SEEK`, `STOP` плеера) | 0 пошло / принята, 1 занято, 2 нет сервиса, 3 вход не тот, 4 нет такой команды | есть |
| `#A0` | `JOB_STATUS` | — | статус задания, прогресс 0..100, слот лога, байт в логе (4) | есть |
| `#A1` | `JOB_LOG` | — | начало лога (до 512 байт); целиком — `SLOT_READ` слота лога | есть |
| `#A2` | `JOB_STOP` | — | — | есть |
| `#B0` | `CFG_GET` | тег (4 знака) | значение | план |
| `#B1` | `CFG_SET` | тег, значение | — | план |
| `#B2` | `CFG_SAVE` | — (записать конфиг во флеш) | — | план |
| `#C0` | `MODE` | состояние: `AY` — карта по умолчанию: все плагины выкл (FX, самоплеер Atari), чип и тень — тишина (R7 `#3F`, громкости 0), дальше чип у Спектрума; работает и из самоплеера | 0 — сделано, FF — нельзя (`UPDATE` / `TEST`) | есть |

## 3. Состояние и байт статуса (чтение `#C0`)

| Биты | Что | Значения |
|---|---|---|
| 1..0 | состояние чипа | 0 `AY` (по умолчанию: команды Спектрума + FX), 1 `PLAY` (самоплеер), 2 `UPDATE`, 3 `TEST` |
| 3..2 | задание | 0 нет, 1 идёт, 2 готово, 3 ошибка |
| 4 | FX включены | |
| 5 | ошибка карты (код — в `INFO`) | тест чипа не прошёл, конфиг побит, откат прошивки |
| 6 | к последнему служебному пакету есть ответ — читать из `#C1` | до следующего пакета |
| 7 | занято — служебный пакет разбирается (с метки `#80` до ответа) | метку ставит железо, снимает ядро |

Переходы: `AY -> PLAY` — `SVC_CALL` плеера («играть»; из FX тоже — карта сама делает `MODE AY`: любой вызов SDK
открывает поток ключом, а ключ в `AY` включает FX); `PLAY -> AY` — `STOP`, `MODE AY`, сброс, ошибка плеера; `UPDATE` / `TEST` —
только из `AY`. Сброс — всё в `AY`, тишина. В `PLAY` записи Спектрума в AY до чипа не доходят (тень и чтение работают).
**Инициализация любого плеера через SDK шлёт `MODE AY`.** Задание — не состояние: идёт в `AY` и `PLAY`.
Программа: `SVC_CALL` -> опрос статуса (показывать прогресс) -> «готово» / «ошибка» — сама решает, что дальше.

## 4. Слоты

Слот — контейнер данных на карте: номер 1..16 (0 — нет; пул RP-AY — 128К), тип, размер, временный (ОЗУ, пропадает при сбросе) или
постоянный (флеш RP; SD — у RP-GS). **Слот 255 — конфиг этой RP** (постоянный, всегда есть).

| Тип | Что | Статус |
|---|---|---|
| `LOG ` | **лог задания:** текст, строка на событие — что потеряно / не получилось / итог (8К); FT2 выводит его в лог Disk после задания. Слот создаёт `SVC_CALL`, освобождает следующий `SVC_CALL` | есть |
| `CFG ` | конфиг RP: блоки тег + длина + версия, две копии + CRC | план |
| `FT2C` | трек FT2 (`FT2/doc/formats/ft2.md`) | план |
| `BTP ` | проект Bitphase (`FT2/doc/formats/btp.md`) | план |
| `MYM ` | maxYMiser (`FT2/doc/formats/mym.md`) | план |
| `SNDH` | музыка Atari для самоплеера (сервис 1) | есть |
| `STAT` | состояние плеера, 32 байта (младшим вперёд): +0 кадров сыграно 4, +4 длина в кадрах 4 (0 — нет в файле), +8 песня, +9 песен, +10 флаги (бит 0 пауза, бит 1 перемотка), +12 мкс счёта кадра 2 и пик 2 (из 20000), +16 опозданий 4, +20 записей потеряно 4. Выход плеера: слот выхода 0 — карта создаёт сама | есть |
| `YM  `, `PSG ` | музыка для самоплеера | план |
| `PRST` | пресеты карты (todo п.63) | план |
| `FW  ` | образ прошивки | план |

## 5. Сервисы

Сервис — блок прошивки: номер, версия, имя, тип входа, тип выхода, команды. Регистрация — строка в таблице
сервисов RP. AY-сервисы — в RP-AY, GS-сервисы — в RP-GS.

| № | Сервис | RP | Вход -> выход | Команды | Статус |
|---|---|---|---|---|---|
| 1 | плеер | AY | `SNDH` -> играет на чипе 0, φM 4 МГц (рев А), состояние — слот `STAT` | 1 `PLAY` (параметр 0 — песня, 0 = первая), 2 `STOP`, 3 `PAUSE` (параметр 0: 1 пауза, 0 дальше), 4 `SEEK` (параметры 0..3 — кадр 20 мс; назад — машина с начала). Задание идёт, пока играет; прогресс — позиция / длина | есть (на ПК-модели; на железе — с плагином) |
| 2 | конвертер | AY | `BTP` / `MYM` / MOD -> `FT2C` + лог | `RUN` | план |
| 3 | обновление | AY / GS | `FW` -> прошивка | `RUN` | план |
| 4 | тест карты | AY | любой слот -> лог (CRC32 слота; образец сервиса) | `RUN` | есть |

| Вызов | Вход | Выход | Статус |
|---|---|---|---|

| `Ayfx_Detect` | после `Ayfx_SvcState` = ответ | `A = 1`, NZ — карта есть (`"TRIN"`) | есть |

| `Job_Status` / `Job_Log` / `Job_Stop` | | | план |
| `Cfg_Get` / `Cfg_Set` / `Cfg_Save` | тег, значение | | план |
| `Play_File` | файл | `Slot_New` + `Slot_Write` + `Svc_Call` плеера | план |
| `Ayfx_ModeAy` | чип выбран | шлёт `MODE AY` (с меткой); итог — `Ayfx_SvcState` / `Ayfx_SvcReply`: 0 — сделано, `FF` — нельзя. Звать при инициализации любого плеера | есть |

Прерывания SDK не трогает (ни `DI`, ни восстановления выбора `#FFFD`): за то, чтобы музыка в прерывании не влезла
между выбором регистра и доступом, отвечает программа — как при любой работе с AY (решение пользователя, 2026-11-07).

Плееры FT2 и игр шлют реалтайм-пакеты (`ROW` / `TABLE` / `RESET`) напрямую — так быстрее (`FT2/srs/player.asm`, `Fx_*`).

## 7. Канал драйвера RP-GS (порты GS)

Настройки, нагрузка и версии RP-GS. Порты `#BB` / `#B3`, новых нет. Команды из свободных в GS и NeoGS (`doc/trinity-sources.md`): без ключа ничего не делают, как в ПЗУ. API: `sdk/trinity_gs.asm`, подключить и вызывать; описание каждой процедуры - в нём. Первым `Gsc_Detect`: есть ли карта. Только для драйвера. Номера команд и кодов, ключ заданы именами в двух местах: `engine/gs/gs_ctl.h` и этот SDK; сменить номер - правка там и в этой таблице.

| Команда `#BB` | Перед ней в `#B3` | Что |
|---|---|---|
| `#FB` | байт ключа `TRINITY` | неверный байт - ключ с начала; после `Y` канал открыт, ответ `#B3`: версия протокола |
| `#FC` | байт пакета | только в открытом канале |
| `#FD` | - | закрыть канал |
| любая другая | | закрывает канал и выполняется как обычно |

Пакет: `[код][длина 2 байта][данные до 16]`. Ответ из `#B3`: `[длина 2 байта][данные]`. Числа младшим байтом вперёд. Пока пакет выполняется, бит команды стоит: запись во флеш видна как занято. Настоящий GS на ключ не отвечает: нет ответа за время ожидания - карта не наша. Пока открыт поток загрузки (`#30` / `#38` без `#D2`), байты ключа попадают в модуль и портят его, канал не открывается. После `#D2` всё работает, модуль загрузить заново.

| Код | Имя | Данные | Ответ |
|---|---|---|---|
| `#D0` | `CFG_GET` | тег 4 знака | значение 4 байта / `FF` |
| `#D1` | `CFG_SET` | тег, значение 4 байта | `0` / `FF` (нет тега, вне пределов, только чтение). Сбрасывает пик и опоздания |
| `#D2` | `CFG_SAVE` | - | `0` / `FF`. Запись во флеш только этой командой |
| `#D3` | `PRESET` | 0 Clean, 1 A500, 2 A1200, 3 HiFi | `0` / `FF`. Сбрасывает пик и опоздания |
| `#D4` | `STAT` | - | нагрузка 2, пик 2 (0.1 %), опоздания 4, блоки 4, частота вывода 4 (Гц), такт 4 (кГц), режим 1, устройство 4 знака |
| `#D5` | `STAT_RESET` | - | `0` |
| `#D6` | `CURVE` | ступень: 0 RC, 1 ФНЧ, 2 LED, 3 ФВЧ, 4 НЧ, 5 ВЧ; `FF` - итог | 32 числа со знаком, 0.01 дБ; частоты `20 * 1000^(i/31)` Гц |
| `#D7` | `VERSION` | - | протокол 1, прошивка 2 |
| `#D8` | `SD` | диск: `0` (или без данных) SD, `1` тестовый (16 секторов в ОЗУ RP, номер по модулю 16) | `0` / `FF` (нет диска). Включает шлюз секторов: дальше команды шлюза, канал закрыт |

**Шлюз секторов (SD карты).** Протокол GS-части драйвера SD NeoGS (WC `SD_NGS.ASM`), сектора сырые по 512 байт, файловую
систему ведёт Спектрум. Вход: пакет `#D8` или драйвер NeoGS, залитый в GS (`#14` / `#13`) и узнанный по отпечатку
(CRC32 первых 45 байт). SDK: `Gsc_Sd_Open` (A - диск, как у `#D8`) / `Gsc_Sd_Read` / `Gsc_Sd_Write` / `Gsc_Sd_Close`.
Тестовый диск - для теста шины без SD (`tools/gsbustest`).

| Команда `#BB` | До / после | Что |
|---|---|---|
| `#20` | - | включить SD; ответ `#B3`: `0` готова, `1` нет |
| `#10` / `#12` | до: в `#B3` число секторов (`0` = 256); после: номер 4 байта младшим вперёд, команда `0`, пустой байт | читать / писать: 512 байт на сектор по биту данных, в конце команда `0` и ждать снятия бита команды (запись - уже на SD) |
| `#F3` / `#F4` | - | выход: перезапуск GS, модуль стёрт; карта перемонтирует SD |
| другие | | ничего не делают |

Пустой байт после номера карта глотает на шине (бит данных не ставит): драйвер NeoGS сразу ждёт бит данных, а RP
могла бы не успеть забрать байт. И данные сектора карта выдаёт только после того, как пустой байт проглочен (иначе
Спектрум примет пустой байт за данные). Для драйверов NeoGS есть и обычные команды GS: `#14` загрузить (длина 2, адрес 2,
байты), `#13` перейти (адрес 2) - код не хранится, только отпечаток; `#1D` прочитать `#20xx`: по `#2000` - `#8B`, как ПЗУ NeoGS.
