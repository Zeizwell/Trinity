# CPLD карты: шпаргалка

Исходник `cpld/rtl/top.v`, проект Quartus `cpld/syn/`, тест `cpld/tb/tb.v`. Чип EPM3128ATC100-10N, ножки из `KiCad/trinity/gen/cpld_gen.py`.

**Статус:** собрано в Quartus II 13.0sp1 (13.1 MAX3000A не поддерживает): 95 / 128 макроячеек, 72 / 80 ножек, Fmax 52.4 МГц при 32 (запас 12.15 нс), SVF делается. Тест `tb.v` (Icarus Verilog, `D:_WorkToolsiverilog`) проходит и ловит 9 намеренных поломок кода. Он проверяет логику на моей модели Z80 и RP; на железе не проверено.

Сборка из `cpld/syn`, Quartus в `D:\_Work\Tools\quartus\quartus\bin64`:
`quartus_sh --flow compile trinity_cpld`, затем `quartus_cpf -c -q 10MHz -g 3.3 -n p trinity_cpld.pof trinity_cpld.svf`.

## Что откуда взято

| Что | Откуда | У нас |
|---|---|---|
| Цикл по такту: `RD` / `WR` при `MREQ` = 1, `M1` = 1, спад 32 МГц | MultiSound `cpld/rtl/top.v` | для AY, но по фронту: от спада до фронта логика не успевает (18.5 нс при 15.6) |
| `IORQ` + `RD` / `WR`, порты `#B3` `#BB` `#33` | NeoGS `zxbus.v` | так же, по такту (см. ниже) |
| `IORQGE` комбинационно по адресу, `M1` = 1 | MultiSound Max, NeoGS | так же |
| Запись: данные снимаем у заднего фронта `WR` | NeoGS (`posedge zxiowr_n`) | последний снимок по такту, пока `WR` = 0 |
| AY `#FFFD` по A15..13 и A3..0, `#BFFD` | MultiSound | у него запись и по `#DFFD`, у нас нет: это порт памяти |
| Данные через CPLD, без 245 | MultiSound | так же |

## Почему не асинхронно

Строб «`WR` без `MREQ`» дёргается в конце записи в память: `MREQ` и `WR` поднимаются почти вместе. Защёлка по его фронту ловит ложный импульс на адресах вида `#xxxD`, поэтому AY только по такту, как у MultiSound. `WAIT` тоже по такту: нет такта от RP, значит нет и `WAIT`, Спектрум не висит.

## Запирание по выборке из ПЗУ

Не сделано. У образцов оно закрывает только порты, совпадающие с TR-DOS (SAA `#FF`, SounDrive). У нас таких нет (config п.21). Появится такой порт — брать из MultiSound Max: `posedge (M1 & MREQ & RD)`.

## Обмен с RP

- **Запись:** цикл кончился → код и данные на ножках → такт → строб 0 на 125 нс → такт. Итого ~220 нс; ближайший `OUT (C),r` на 14 МГц через 857 нс.
- **Чтение:** код, строб `RD` = 0, `WAIT` = 0. RP кладёт ответ, потом поднимает `RDY`. CPLD снимает данные, отпускает `WAIT`, держит их на шине до конца `RD`. Строб `RD` поднимается в конце цикла: тогда RP отпускает шину и опускает `RDY`.
- **RP молчит:** через 64 такта (2 мкс) `WAIT` отпущен, ответ `#FF`.
- **Маска (config п.38):** RP-GS кладёт на `GS_D` биты (0 GS, 1 OPL, 2 AY) и поднимает `RDY` вне чтения хотя бы на 3 такта (берётся только подъём), данные держит, пока `RDY` не опустит. После включения маска 0: порты не отвечают, `IORQGE` не держится, пока RP-GS не загрузилась. `/RST` маску не трогает. Менять её в момент записи с шины нельзя (столкновение на `GS_D`): только сразу после обработанной команды.

## Бюджет WAIT на 14 МГц

Z80 смотрит `WAIT` на спаде TW: 1.5 такта от начала `RD` = 107 нс. У нас: до 31 нс до снимка + 31 нс до решения + ~10 нс выход = ~72 нс. Остаётся ~35 нс на установку у Z80 и задержки шины Евы; проверить на плате.
